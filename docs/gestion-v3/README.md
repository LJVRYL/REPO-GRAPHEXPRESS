## Numbering and compatibility
MU loader initializes an additive class after plugins_loaded. Two independent feature flags default off. Explicit migration creates {prefix}ge_work_numbers InnoDB with work_number BIGINT AUTO_INCREMENT starting 10001 and UNIQUE quote_id/order_id. No MAX+1 option counter. Allocator uses INSERT IGNORE, rereads the authoritative row, and fails closed on error. Conversion atomically binds only the unbound/same order row, and rejects a competing second order. WooCommerce save swallows Exception, so hook wrapper wp_die(409) prevents a false successful conversion. Single populated first-save checkout is covered by after-save hook. Registry is authoritative; meta _ge_work_number is a mirror, not allocator.

Legacy cutoffs captured on first activation: quote ID980, order ID978. Existing references and technical primary keys are unchanged; converting old quotes remains historical. New commercial quote reserves a number; conversion inherits it; a manual/normal operational order gets its own. Abandoned, trashed or deleted quote does not delete its registry row. Gaps from concurrent insert retries are acceptable and never recycled. Payment attempts/refunds/per-item technical suborders are not new commercial jobs. URLs still contain technical IDs. Read helpers continue to show issued numbers even with allocation disabled.

Global search resolves exact work_number to both quote/order and queries customer name/email/phone/company, current quotes, suppliers, artwork-library metadata, quote artwork metadata and order documents. It exposes links to existing protected views, not private storage locations. It is bounded to 10 per category. Local historical quote search remains comprehensive within the unified history; generic orders retain inherited recent-250 cap, production generic text remains current page. Exact commercial lookup bypasses those caps.
